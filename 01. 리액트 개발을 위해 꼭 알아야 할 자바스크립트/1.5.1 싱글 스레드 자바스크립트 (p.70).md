## 1.5.1 싱글 스레드 자바스크립트

### 핵심 개념 요약

자바스크립트는 싱글 스레드 언어이다. ⇒ 한번에 하나의 작업만 동기 방식으로 처리할 수 있다.

**프로세스(process)란?**

⇒  프로그램을 구동해 프로그램의 상태가 메모리 상에서 실행되는 작업 단위를 의미

⇒ 즉, 하나의 프로그램 실행은 하나의 프로세스를 가지고 그 프로세스 내부에서 모든 작업이 처리 됨

**스레드(thread)란?**

⇒ 소프트웨어의 복잡성으로 인해 하나의 프로그램에서 동시에 여러 개의 복잡한 작업을 수행할 필요가 있게 됨

⇒ 더 작은 실행 단위로, 하나의 프로세스에서는 여러 개의 스레드를 만들 수 있다.

⇒ 스레드는 서로 메모리를 공유할 수 있어 여러가지 작업을 동시에 수행 할 수 있게 되었다.

**멀티스레드** 

→ 내부적으로 처리가 복잡하다는 단점이 있다. 

→ 하나의 프로세스에서 동시에 서로 같은 자원에 접근 할 수 있어 같은 자원에 대해 여러번 처리하거나 하는 동시성 문제가 발 생 할 수 있다.

→ 각각 격리되어 있는 프로세스와 다르게 하나의 스레드에 문제가 발생하면 다른 스레드에도 동시에 문제가 발생 할 수 있다.

- ***최초의 자바스크립트는 브라우저에서 HTML을 그리는데 한정적인 도움을 주는 보조적인 역할로 만들어 졌다.***
    - 1995년 시작됨 (멀티 스레드에 대한 개념이 대중화 되던 시기가 아님)
    - 1995년 넷스케이프 개발자가 브라우저에서 간단한 스크립트를 지원하는 LiveScript를 만들었다.(자바스크립트의 시작)
        - 10일 만에 완성 되었으며, 버튼 위에 이미지를 띄우거나, 경고창, 폼 처리 등의 기초적인 수준에서 제한적 사용
        - 멀티스레딩을 지원했다면 DOM 조작의 동시적 타이밍 이슈가 발생해 이슈가 있었을 것
    - 1995년엔 싱글 스레드 언어로 구현한 것이 당시엔 더 합리적 이었을 것!

**싱글 스레드 자바스크립트**

- 자바스크립트 코드의 실행이 하나의 스레드에서 순차적으로 이루어진다는 것을 의미 (코드를 한 줄 한 줄 실행)
- 하나의 작업이 끝나기 전까지 뒤의 작업이 실행되지 않는다는 것
- C, 메이저 프로그래밍 언어에서는 임의로 멈추고 먼저 실행 가능

<aside>
💡

Node.js에서 새롭게 추가된 Worker나 브라우저에서 제공하는 WebWorker를 활용하면 동시에 여러작업을 처리할 수 있지만 본 절에서는 논외로 한다.

</aside>

- 하나의 코드가 실행하는데 오래 걸리면 뒤의 코드가 실행되지 않는 특징 “*Run-to-completion*” **이라고 한다.
- 동시성을 고민할 필요가 없다는 장점이 되면서, 때에 따라서 웹페이지에서는 멈춘 것 같은 느낌을 줄 수 있다.
- “*Run-to-completion*” 즉, *‘동기식’* 으로 한번에 순차적 처리 된다.

**비동기**

- ‘*Asynchronous*’ 즉, 동시에 일어나지 않는 다는 것을 의미한다.
- 동기식과 다르게 요청한 즉시 결과가 주어지지 않을 수도 있어 응답이 언제 올지 알 수 없지만 여러 작업을 동시에 수행할 수 있다.

```jsx
console.log(1)

setTimeout(() => {
	console.log(2)
}, 0)

setTimeout(() => {
	console.log(3)
},100)

console.log(4) // 결과 : 1, 4, 2, 3
```

- 위의 코드를 이해하기 위해서는 ‘*이벤트 루프’* 개념을 이해해야 한다.
