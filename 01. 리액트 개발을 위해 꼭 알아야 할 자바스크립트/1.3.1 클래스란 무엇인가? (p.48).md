## 1.3.1 클래스란 무엇인가?

### 핵심 개념 요약

자바스크립트 클래스란? 특정한 형태의 객체를 반복적으로 만들기 위해 사용되는 것으로 일종의 템플릿의 개념으로 볼 수 있다. ES6 이전에는 클래스라는 개념이 없어 객체를 만드는 역할을 함수가 도맡아 했다. 즉, 자바스크립트 클래스로 하는 모든 것들을 함수로도 동일하게 표현할 수 있다.

**생성자(constructor)**

- 객체를 생성하는 데 사용하는 특수한 메서드로, 단 하나만 존재할 수 있다. (여러개 사용시 에러)
- 생성자에서 별다르게 수행할 작없이 없다면 생략하는 것도 가능하다.

```jsx
class Car { // error
	constructor(name) {
		this.name = name
		}

 constructor (name) { //SyntaxError: A class may only have one constructor
	 this.name = name
	}
}

----

class Car { 
	// constructor는 없어도 가능
}
```

**프로퍼티**

- 클래스로 인스턴스를 생성할 때 내부에 정의할 수 있는 속성 값

```jsx
class Car {
	constructor(name){
		// 값을 받으면 내부에 프로퍼티로 할당된다.
		this.name = name
	}
}

const myCar = new Car('자동차') // 프로퍼티 값 넘김
```

- 기본적으로 인스턴스 생성시 constructor 내부에는 빈 객체가 할당돼 있는데 이 빈 객체에 프로퍼티의 키와 값을 넣어서 활용 할 수 있게 도와 준다.
- 자바스크립트에서 기본적으로 모든 프로퍼티가 public이다.
- 타입스크립트를 활용하면 다른 언어와 마찬가지로 private, protected, public을 사용할 수 있다.
- (참고사항) #을 붙여서 private을 선언하는 방법 추가 - ES2019

```jsx
class Person {
	#name;
	#age;
	constructor(name, age) {
    // private 필드 참조 및 할당
    this.#name = name;
    this.#age = age;
  }
  // private 메서드 선언
  #greet() {
    console.log(`안녕하세요, 제 이름은 ${this.#name}입니다.`);
  }

  // public 메서드
  introduce() {
    this.#greet(); // 클래스 내부에서 private 메서드 호출 가능
    console.log(`나이는 ${this.#age}살 입니다.`);
  }
}

const me = new Person('김철수', 30);
me.introduce(); // "안녕하세요, 제 이름은 김철수입니다.\n나이는 30살 입니다." 출력

console.log(me.#name); // 에러 발생: #name은 클래스 외부에서 직접 접근할 수 없습니다.
me.#greet(); // 에러 발생: #greet은 클래스 외부에서 직접 접근할 수 없습니다.
```

**getter와 setter**

- getter는 클래스에서 무언가 값을 가져올 때 사용한다.
- setter는 클래스 필드에 값을 할당할 때 사용한다.

```jsx
class Car{
	constructor(name){
		this.name = name
	}
}

get firstCharacter(){
	return this.name[0]
}

set firstCharacter(char){
	this.name = [char, ...this.name.slice(1)].join('');
}

const myCar = new Car('자동차');

console.log(myCar.firstCharacter) // 자

myCar.firstCharacter = '차'

console.log(myCar.firstCharacter, myCar.name) //차, 자동차
```

**인스턴스 메서드(프로토타입 메서드)**

- 클래스 내부에서 선언한 메서드를 인스턴스 메서드라고 한다.
- 자바스크립트의 prototype에 선언되므로 프로토타입 메서드로 불리기도 한다. (`Object.getPrototypeOf`)

```jsx
class Car {
    constructor(name) {
        this.name = name
    }
    
    // 인스턴스 메서드 정의
    hello() {
        console.log(`안녕하세요, ${this.name}입니다.`)
    }
}

const myCar = new Car('자동차')
myCar.hello() // 안녕하세요, 자동차입니다.
```

- 위와 같이 생성한 객체에서 클래스에서 선언한 hello 인스턴스 메서드에 접근할 수 있다.
- 이렇게 접근할 수 있는 이유는 이 메서드가 prototype에 선언됐기 때문이다.

```jsx
const myCar = new Car('자동차')
Object.getPrototype(myCar) // {constructor: f, hello: f} f는 함수를 뜻한다.

Object.getPrototypeOf(myCar) === Car.prototype // true

myCar.__proto__ === Car.prototype // true
//__proto__는 권장하지 않는다.
```

- `Object.getPrototypeOf`를 사용하면 인수로 넘겨준 변수의 prototype을 확인할 수 있다.
- `myCar` 객체의 프로토타입이 ``{constructor: f, hello: f}``인 것은 `Car` 클래스가 정의될 때 `myCar`가 `Car.prototype`을 상속받았기 때문이다.
- `{constructor: f}`는 `myCar` 객체를 생성한 생성자 함수(`Car` 함수)를 가리키며, `{hello: f}`는 `Car` 클래스에 정의된 `hello` 메서드가 프로토타입에 추가되어 `myCar` 객체가 접근할 수 있게 되었음을 의미한다.
- `Object.getPrototypeOf(myCar)` 를 `Car.prototype` 와 비교했을 때 true 반환
- 프로토타입과 프로토타입 체이닝 이라는 특성 때문에 생성한 객체에서도 직접 선언하지 않은 클래스에 선언한 hello() 메서드를 호출 할 수 있고, 메서드 내부에서 `this`(프로토타입 체인으로 찾은 메서드를 실행할 때, 그 메서드를 호출한 원래 객체)도 접근해 사용할 수 있게 된다.

> *프로토타입 체이닝
직접 객체를 선언하지 않았음에도 프로토타입에 있는 메서드를 찾아서 실행을 도와주는 것을 말한다. 모든 객체는 프로토타입을 갖고 있는데, 특정 속성을 찾을 때 까지 자기 자신부터 최상위 객체인 Object까지 훑는다.
EX> toString은 객체 어디에서도 선언하는 경우가 없지만 대부분의 객체에서 모두 사용할 수 있다. 이는 프로토타입 체이닝을 거쳐 Object에 있는 toString을 만나기 때문이다.*
> 

**정적 메서드**

- 정적 메서드는 클래스의 인스턴스가 아닌 이름으로 호출 할 수 있는 메서드다.

```jsx
class Car{
	**static** hello() {
    		console.log('안녕하세요!')
    	}
}

const myCar = new Car()

myCar.hello() // Uncaught TypeError: myCar.hello is not a function
Car.hello() // 안녕하세요!
```

- 내부의 `this`는 클래스로 생성된 인스턴스가 아닌, 클래스 자신을 가리키기 때문에 다른 메서드에서 일반적으로 사용하는 `this`를 사용할 수 없다.
- 리액트 클래스 컴포넌트 생명주기 메서드인 `static gerDerivedStateFromProps(props, state)`에서는 `this.state`에 접근할 수 없다.

<aside>
💡

`static getDerivedStateFromProps(props, state)`는 리액트(React) 컴포넌트의 생명주기 메서드로, 프롭스(props)의 변경에 따라 스테이트(state)를 동기화할 때 사용한다. `constructor`와 `render` 메서드 사이에 호출되며, 스테이트를 props와 동기화해야 하는 명확한 이유가 있을 때만 사용해야 한다. 대부분의 경우에는 `componentDidUpdate` 또는 `useEffect` 훅을 사용하는 것이 더 권장되고 있다.

</aside>

- 정적 메서드는 this에 접근할 수는 없지만 인스턴스를 생성하지 않아도 사용할 수 있다는 점, 객체를 생성하지 않아도 여러 곳에서 재사용이 가능하다는 장점이 있다.
- 애플리케이션 전역에서 사용하는 유틸 함수를 정적 메서드로 많이 활용하는 편이다.

**상속**

- 리액트에서 클래스 컴포넌트를 만들기 위해 extends를 사용하는 경우가 종종 있는데, 이 extends는 기존 클래스를 상속받아서 자식 클래스에서 확장하는 개념으로 볼 수 있다.

```jsx
class Car {
 constructor(name) {
        this.name = name
    }
 }
 
 honk() {
	 console.log(`${this.name} 경적을 울립니다!`);
 }
}

class Truck extends Car {
	constructor(name) {
		// 부모 클래스의 constructor, 즉 Car의 constructor를 호출한다.
		super(name)
	}
	
	load() {
		console.log('짐을 싣습니다.');
	}
}

const myCar = new Car('자동차');
myCar.honk() // 자동차 경적을 울립니다!

const truck = new Truck('트럭');
truck.honk() // 트럭 경적을 울립니다!
truck.load() // 짐을 싣습니다.
```

- `Car`를 extends한 `Truck`이 생성한 객체에서도, `Truck`이 따로 정의하지 않은 `honk` 메서드를 사용할 수 있다. (상속)
- extends를 활용하여 기본 클래스를 기반으로 다양하게 파생된 클래스를 만들 수 있다.
