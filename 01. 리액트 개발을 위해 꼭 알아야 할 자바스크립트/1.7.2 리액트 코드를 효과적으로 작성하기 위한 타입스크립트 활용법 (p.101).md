## 1.7.2 리액트 코드를 효과적으로 작성하기 위한 타입스크립트 활용법

### 핵심 개념 요약

타입스크립트는 타입을 얼마나 엄격하게, 적극적으로 활용하느냐에 따라 효용성에 큰 차이를 보인다.

**any 대신 unknown을 사용하자**

- `any`는 불가피할 때만 사용해야 하는 타입으로 처음 작성시 저지르는 실수 중 하나이다.
- 정적 타이핑의 이점을 모두 버리는 것과 같다.
- `any`는 모든 타입을 커버하기에, 어떤 상황에서도 런타임 과정에서 타입 에러를 잡아내지 못함
- `unknown`은 모든 값을 할당할 수 있는 이른바 ***top type***으로, 어떠한 값도 할당 할 수 있지만 바로 사용하는 것이 불가능
- `unknown`으로 선언된 변수를 사용하기 위해서는 ***type narrowing*** 즉, 원래 의도대로 타입을 적절히 좁혀야 한다.

```tsx
function doSomething(callback: unknown) {
  if (typeof callback === 'function') { // typeof를 통해 원하는 타입일 때만 작동하도록 함
    callback();
    return;
  }
  
  throw new Error('callback은 함수여야 합니다.');
}
```

- `never`는 ***top type***인 `unknown`과 반대 되는 ***bottom type***이다.
- never는 어떠한 타입도 들어올 수 없다는 것을 의미하며, 코드상으로 존재가 불가능한 타입을 나타낼 때 never가 사용된다.

```tsx
type what1 = string & number
type what2 = ('hello' | 'hi') & 'react'
```

- 타입스크립트로 컴포넌트를 선언할 때 props는 없지만 state는 존재하는 상황에서 이 빈 props, 정확히 어떤 props도 받아들이지 않는 다는 뜻으로 사용이 가능하다.

```tsx
//string이 키지만 값이 never로 어떠한 값도 올 수 없다.
type Props = Record<string, never>
type State = {
	counter : 0;
}

class SampleComponent extends React.Component<Props, State>{
	constructor(props : Props){
		super(props)
		this.state = {
			counter : 0;
		}
	}
	
	render() {
		return <>...</>
	}
}

export default function App() {
	return(
		<>
			{*/ OK */}
			<SampleComponent />
			{*/ Type 'string' is not assignable to type 'never' */}
			<SampleComponent hello="world" />
		</>
	)
}
```

**타입 가드를 적극 활용하자**

- 타입을 좁히는데 도움을 주는 것으로 조건문과 함께 사용하면 타입을 효과적으로 좁힐 수 있어 명확하게 변수나 함수를 사용할 수 있다.
    
    **instanceof 와 typeof**
    
    - `instanceof`는 지정한 인스턴스가 특정 클래스의 인스턴스인지 확인할 수 있는 연산자이다. ( 반환값 T/F )
    
    ```tsx
    ...
     async function fetchSomthing() {
    	 try{
    		 const response = await fetch('/api/something')
    		 return await response.json()
    	 } catch (e) {
    		 // e는 unknown이다
    		 
    		 // UnAuthorizedError를 위한 타입 가드 조건문
    		 if(e instanceof UnAuthorizedError) {
    		  // do something...
    		 }
    		 
    		 // UnExpectedError를 위한 타입 가드 조건문
    		 if(e instanceof UnExpectedError) {
    		  // do something...
    		 }
    		 
    		 throw e
    	 }
     }
    ```
    
    - `typeof` 연산자는 특정 요소에 대해 자료형을 확인하는데 사용한다. ( 반환값으로 문자열 `"string"`, `"object"`, `"function"` 등이 반환)
    
    ```tsx
    function logging(value : string | undefined) {
    	if(typeof value === 'string') {
    		console.log(value)
    	}
    	
    	if(typeof value === 'undefined') {
    		// nothing to do
    		return
    	}
    }
    ```
    
    **in**
    
    - `property in object`로 사용되는데, 주로 어떤 객체에 키가 존재하는지 확인하는 용도로 사용된다.
    - 객체에만 있는 프로퍼티 값을 확인하며, 여러가지의 객체가 존재할 수 있는 경우 유용하게 사용될 수 있다.
    
    ```tsx
    interface Student {
      age: number;
      score: number;
    }
    
    interface Teacher {
      name: string;
    }
    
    function doSchool(person: Student | Teacher) {
      if ("age" in person) {	
         person.age // person은 Student 타입
         person.score
    	}
    
      if ("name" in person) {
    	   person.name // person은  Teacher 타입
      }
    }
    ```
    

**제네릭 (generic)**

- 함수나 클래스 내부에서 단일 타입이 아닌 다양한 타입에 대응할 수 있도록 도와주는 도구
- 타입만 다른 비슷한 작업을 하는 컴포넌트를 단일 제네릭 컴포넌트로 선언해 간결하게 작성할 수 있다.

```tsx
function getFirstAndLast<T>(list : T[]): [T,T] {
  return [list[0]. list[list.length - 1]];
}

const [first, last] = getFirstAndLast([1, 2, 3, 4, 5])

first // number
last // number

const [first, last] = getFirstAndLast(['a', 'b', 'c', 'd', 'e'])

first // string
last // string
```

- `T`라는 제네릭을 선언해, 이를 각각 배열의 요소와 반환 값의 요소로 사용했다. (`getFirstAndLast` 함수가 다양한 타입 처리가 가능 해짐)
- 리액트에서 제네릭을 사용할 수 있는 대표적인 코드는 `useState`이다.

```tsx
function Component() {
 // state : string
 const [state, setState] = useState<string>('');
 // ...
}
```

- 기본값을 넘기지 않고 사용하는 경우 `undefined`로 추론하는 문제가 발생하는데 제네릭을 사용해 방지할 수 있다.

```tsx
function multipleGeneric<First, Last>(a1: First, a2: Last) : [First, Last] {
	return [a1, a2]
}

const [a, b] = multipleGeneric<string, boolean>('true',true)

a // string
b // boolean
```

- 제네릭을 하나 이상 사용할 경우, 적절히 네이밍하는 것이 좋다.

**인덱스 시그니처 (index signature)**

- 객체의 키를 정의하는 방식을 의미한다.
- 키에 원하는 타입을 부여할 수 있다.
- 동적인 객체를 정의할 때 유용하지만 키의 범위가 너무 커지는 경우 존재하지 않는 키로 접근하면 `undefinded`를 반환할 수 있다.
- 객체의 키는 동적 선언되는 경우를 최대한 지양하고, 객체의 타입도 필요에 따라 좁혀야 한다.

**Record** 

```tsx
// Record를 사용
type HeUo = Record<'hello' | 'hi', string>;

const hello: HeUo = {
  hello: 'hello',
  hi: 'hi',
};

// 타입을 사용한 인덱스 시그니처
type HeUo = { [key in 'hello' | 'hi']: string };

const hello: HeUo = {
  hello: 'hello',
  hi: 'hi',
};
```

- `Record<key, Value>`를 사용하면 객체의 타입에 각각 원하는 키와 값을 넣을 수 있고, 인덱스 시그니처를 타입을 사용해 원하는 형태로 객체를 좁힐 수 있다.

**as로 타입을 단언하기**

- 객체에 인덱스 시그니처를 사용했을 때, 다음과 같은 이슈를 마주할 수 있다.

```tsx
Object.keys(hello).map((key) => {
	// Element implicitly has an 'any' type because expression of type 'string'
	// can't be used to index type 'Hello'.
	// No index signature with a parameter of type 'string' was found on type 'Hello'
	const value = hello[key]
	return value
})

//string[]
const result = Obeject keys(hello)
```

- `hello`객체의 `key`를 `Object.key`로 잘 뽑아 냈고, 그 키로 객체에 접근했지만 에러 발생
- `Object.keys`가 `string[]`을 반환하는데, 이 `string`은 `hello`의 인덱스 키로 접근할 수 없기 때문

*해결 방법은 ?*

- 타입스크립트의 `Object.keys`에 대한 반환 타입을 `string[]` 대신 개발자가 단언한 타입으로 강제하는 방법

```tsx
// Object.keys(hello)를 as로 타입을 단언하는 방법
(Object.keys(hello) as Array<keyof Hello>).map((key) => {
	const value = hello[key]
	return value
})
```

- keyOf라고 하는 Object.keys를 대신할 함수를 만드는 방법으로 객체의 키를 가지고 오면서 동시에 가져온 배열에 대해서도 타입 단언으로 처리하는 과정을 거친다.

```tsx
// 타입 가드 함수를 만드는 방법
function keysOf<T extends Object>(obj : T): Array<keyof T>{
	return Array.from(Object.keys(obj)) as Array<keyof T>
}

keysOf(hello).map((key) => {
	const value = hello[key as keyof Hello]
	return value
})
```

- 가져온 키를 단언하는 방법

```tsx
// key를 keyof Hello 타입으로 단언하여 정확한 타입을 지정
Object.keys(hello).map((key) => {
  const value = hello[key as keyof Hello]; // key를 keyof Hello로 단언
  return value;
});
```

> *타입스크립트의 핵심 원칙 중 하나는 타입 검사가 값의 형태에 초점을 맞춘다는 것입니다. 이를 “덕 타이핑” 또는 “구조적 서브타이핑”이라고 부르기도 합니다.
출처 : 타입스크립트 인터페이스 소개란*
> 
- 타입스크립트의 핵심 원칙은 타입 체크를 할 때 그 값이 가진 형태에 집중한다는 것 (덕 타이핑, 구조적 타이핑)
- 자바스크립트는 객체의 타입에 구애받지 않고 객체의 타입에 열려 있으므로 타입스크립트도 이러한 특징을 맞춰주어야 한다.
- 타입스크립트는 모든 키가 들어올 수 있는 객체의 키에 포괄적으로 대응하기 위해 타입을 제공
