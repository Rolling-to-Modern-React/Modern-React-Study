## 2.3.2 함수 컴포넌트 (Function Component)

### 핵심 개념 요약

#### 함수 컴포넌트의 등장 배경
- **React 16.8 이전**에는 함수 컴포넌트가 단순히 **“무상태(stateless) 컴포넌트”** 역할만 수행했다.  
- **React 16.8 이후**에는 **Hook**(useState, useEffect 등)이 도입되면서  
  함수 컴포넌트도 상태(state)와 생명주기(lifecycle) 로직을 다룰 수 있게 됐다.  
- 이 변화로 인해 함수 컴포넌트는 **클래스 컴포넌트의 대체 구조**로 자리 잡았다.

---

#### 기본 예제

```tsx
import { useState } from 'react'

type SampleProps = {
  required?: boolean
  text: string
}

export function SampleComponent({ required, text }: SampleProps) {
  const [count, setCount] = useState<number>(0)
  const [isLimited, setIsLimited] = useState<boolean>(false)

  function handleClick() {
    const newValue = count + 1
    setCount(newValue)
    setIsLimited(newValue >= 10)
  }

  return (
    <h2>
      Sample Component
      <div>{required ? '필수' : '필수 아님'}</div>
      <div>문자: {text}</div>
      <div>count: {count}</div>
      <button onClick={handleClick} disabled={isLimited}>
        증가
      </button>
    </h2>
  )
}
```

---

#### 주요 특징 비교 (클래스 컴포넌트 vs 함수 컴포넌트)

| 구분 | 클래스 컴포넌트 | 함수 컴포넌트 |
|:--|:--|:--|
| **상태 관리** | `this.state` / `setState()` 사용 | `useState()` 등 Hook 사용 |
| **this 바인딩** | 필요 (`this.handleClick = this.handleClick.bind(this)`) | 불필요 (`function` 내부에서 직접 사용) |
| **라이프사이클** | `componentDidMount`, `componentDidUpdate`, `componentWillUnmount` | `useEffect()` 하나로 통합 관리 |
| **props 접근** | `this.props` | 인자 구조분해로 직접 접근 |
| **가독성 / 간결성** | 상대적으로 복잡 | 짧고 선언적 |
| **성능** | 내부적으로 인스턴스 생성 비용 존재 | 상대적으로 가벼움 |

---

#### 장점 요약

1. **간결한 문법** — 클래스 없이 순수 함수로 작성 가능  
2. **this 바인딩 불필요** — 함수 스코프 내에서 자연스럽게 동작  
3. **Hook 사용 가능** — 상태 관리와 사이드 이펙트를 함수형으로 구현  
4. **가벼운 구조** — 인스턴스 생성이 없어 메모리 효율적  
5. **테스트 용이성** — 순수 함수 기반이라 유닛 테스트가 간단함  

---

#### state 관리 방식의 변화

- 클래스형은 `state`가 **하나의 객체**로 관리됨
  ```js
  this.state = { count: 0, isLimited: false }
  this.setState({ count: newValue })
  ```
- 함수형은 `useState`로 **각각의 상태를 독립적으로 관리**함
  ```js
  const [count, setCount] = useState(0)
  const [isLimited, setIsLimited] = useState(false)
  ```

→ 더 세밀한 상태 제어가 가능하며, 불필요한 객체 병합 과정이 사라짐.

---

### 질문 및 토론 사항
- 함수형 컴포넌트는 매 렌더링마다 다시 호출되는데, 그에 따른 성능 이슈는 어떻게 방지할 수 있을까?
  함수형 컴포넌트는 매 렌더링마다 다시 호출되지만,
  내부 연산이나 객체 생성으로 인한 성능 낭비를 최소화하려면 메모이제이션(Hooks)으로 최적화한다.
  (useMemo / useCallback / React.memo 등을 활용해 불필요한 연산, 함수 재생성, 자식 리렌더링을 막으면 성능 이슈는 충분히 제어가 가능)
