## 1. 메모이제이션이 항상 좋은 건 아니다.

```js
function sum(a, b) {
  return a + b;
}

```

- 위의 예시처럼 단순히 두 숫자를 더하는 아주 간단한 함수가 있다.
  이런 연산 결과를 굳이 메모이제이션하여 캐시에 저장하는 것이 과연 이득일까?

### **메모이제이션을 적용하면 실제 계산 전에 다음과 같은 작업들이 필요하다.**
- 1)캐시에 해당 값이 있는지 확인함
- 2)캐시 내부를 탐색해 일치하는 항목을 찾아야 함
- 3)값이 있으면 캐시에서 꺼내고, 없으면 계산한 뒤 캐시에 다시 저장함
- 즉, 단순히 `1+1`을 계산하는 것보다 캐시를 탐색하고 비교하고 저장하는 과정 자체가 더 큰 비용을 발생시킬 수 있다.
> ! 상황을 잘못 판단해서 적용하면 오히려 성능을 떨어뜨릴 수 있다. (작고 가벼운 작업에는 적용 X)

## 2. 리액트에서 메모이제이션 남발이 안좋은 이유
- `React.memo(),useMemo(),useCallback()` 같은 메모이제이션 훅을 남발하면 오히려 성능을 떨어뜨릴 수 있다.
- props 비교, 메모리 저장, 렌더 타이밍 판단등에 부가 비용이 꽤 크게 들어간다.
- 리액트 핵심 개발자 Dan Abramov : “모든 컴포넌트를 memo로 감싸지 마세요.”

## 3. 언제 메모이제이션을 써야 할까?
- 1)비용이 큰 연산이 반복될 때(긴 리스트 정렬, 무거운 계산, 복잡한 로직 재사용)
- 2)리렌더링으로 인한 낭비가 눈에 띌 때(무거운 UI 컴포넌트, props가 거의 안바뀌는 자식 컴포넌트 등)

## 4. 결론
- 메모이제이션은 기본적으로 쓰는 기술이 아니라 필요할 때만 쓰는 특수한 최적화 기술이다.
- 가볍게 계산 가능한 부분 또는 복잡하지 않은 컴포넌트에 적용하면 오히려 성능이 떨어진다.

### 질문 및 토론 사항
## 어떤 기준으로 메모이제이션 적용 여부를 판단할까?
- step1. 느린가? 느리면 원인을 분석한다. (렌더링, 정렬, 재계산 등)
- step2. 중복 계산인가? 중복 계산이면 메모이제이션 적용 
- step3. 비용보다 이득이 더 큰가? useMemo/useCallback/ memo 유지 비용이 더 크면 쓰면 안 됨
